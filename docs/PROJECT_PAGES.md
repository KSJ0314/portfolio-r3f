# 프로젝트 상세 페이지 (PROJECT_PAGES)

> 전시 칸을 확대했을 때 보이는 프로젝트별 상세를 채우는 절차와 기준.
> 프로젝트 하나를 작업할 때마다 이 문서를 보고 한 단계씩 진행한다.
> 구조가 어떻게 도는지는 [ARCHITECTURE.md](./ARCHITECTURE.md)의 전시 공간 항목 참고.

## 어떤 화면인가

전시 칸의 액자를 누르면 카메라가 그 칸을 정면으로 확대하고, 액자 앞에 **16:9 판**이 서서 상세를
보여준다. 판 안의 내용만 페이지 단위로 교체되고 판과 카메라는 그대로다.
하단 인디케이터와 좌우 버튼으로 페이징 처리한다.

읽는 사람은 전시관을 걸으며 칸을 하나씩 열어 본다. **칸마다 구성이 다르면 매번 어디를 봐야 할지
다시 찾게 되므로 장 순서는 고정한다.**

## 1. 페이지 구성 표준

**순서는 고정, 장수는 프로젝트마다 다르다.**

| 장 | 담을 것 |
|---|---|
| 첫 장 | 프로젝트 이름, 한 줄 소개, 요약, 기간·팀, 성과. **GitHub·노션 링크** |
| 문제 | 무엇이 불편했고 그것을 어떻게 풀었는지. 기능 나열이 아니라 이유 |
| 맡은 것 | 전체 중 본인이 만든 범위와 기여도. 본인이 쓴 기술과 고른 이유 |
| 기능 | 핵심 기능 한둘을 화면 위주로. 글보다 그림이 앞선다 |
| 트러블슈팅 | 증상 → 원인 → 해결 → 결과. 한 장에 하나 |
| 회고 | 배운 것과 아쉬운 것. 짧게 |

재료가 적으면 **문제와 맡은 것을 한 장으로 합치거나 트러블슈팅을 하나만 둔다.** 억지로 장수를
맞추면 빈 장이 생긴다. 4~7장 사이가 적당하다.

### 담지 않는 것

- 폴더 구조·ERD·인프라 아키텍처 다이어그램. 넘겨 보는 판에서는 읽히지 않고, 상세는 노션 몫이다.
- **본인이 맡지 않은 영역의 스택.** 실어 두면 면접에서 그쪽을 묻는다.
- 기술 로고만 늘어놓은 장, 개발 일정표, 회의록, 커밋 수 같은 지표.

## 2. 자료 준비

사진과 영상은 **`public/images/projects/<key>/`** 에 둔다. `<key>`는 그 프로젝트의 번호다(4번 항목).

- **`cover.jpg`는 이름이 고정이다.** 액자에 걸리는 표지라 다른 이름으로 두면 액자가 빈 회색 판으로 남는다.
- 그 밖의 파일 이름은 페이지에서 쓰는 이름을 그대로 적으면 된다.
- 판이 16:9라 캡처도 그 비율로 잘라 두면 사방에 여백이 덜 남는다.

### 움직이는 화면은 GIF가 아니라 영상으로

**GIF는 첫 장에서 멈춘다.** 3D 판에 얹는 텍스처는 이미지 한 장을 GPU에 올리는 것이라, 브라우저가
알아서 넘겨 주는 `<img>`와 달리 프레임이 넘어가지 않는다.

그래서 움직이는 화면은 **mp4(또는 webm)** 로 두고 영상 텍스처로 얹는다. 용량도 GIF보다 훨씬 작다.

- 소리 없이 저절로 돌아야 하므로 `muted` · `loop` · `playsInline`이 필요하다. 특히 `muted`가 없으면
  브라우저가 자동 재생을 막는다.
- 페이지를 넘겨 보이지 않는 동안에는 멈춘다. 안 보이는 영상이 계속 도는 것을 막기 위함이다.

## 3. 페이지 안의 좌표

페이지 안은 월드 좌표가 아니라 **가로 1 기준 정규화 좌표**다. 판 가로가 1이고 원점이 한가운데이며,
세로는 `height` props로 받는다(16:9면 약 0.5625).

**글자 크기·여백·자리를 전부 가로 대비 비율로 적는다.** 그래서 칸 크기나 방 배율이 바뀌어도 페이지
안 구도가 그대로이고, 나중에 인쇄(Phase 9)나 2D 모아보기로 옮길 때도 배율만 갈아 끼우면 된다.

받는 props는 `contents/contents.types.ts`의 `ProjectPageProps`에 있다.

## 4. 프로젝트를 가리키는 번호(`key`)

프로젝트는 이름이 아니라 **번호**로 가리킨다. 이름은 바뀔 수 있고 한글이라 경로에 인코딩이 붙는다.

`key`는 Firestore `projects` 문서의 필드이고 0부터 올라간다. 사진 폴더 이름
(`public/images/projects/<key>/`)과 페이지 정의 폴더 이름(`contents/<key>/`)이 모두 이 값이다.

**새 프로젝트를 더할 때는 Firestore 문서에 `key`를 넣는 것이 먼저다.** 없으면 액자는 회색 판으로
남고, 페이지는 등록 전과 같이 자리표시(`PlaceholderPages`)가 나온다.

## 5. 글은 전부 여기에 쓴다

**페이지에 들어가는 글은 Firestore에서 끌어오지 않고 `contents/<key>/`에 직접 쓴다.** 제목·기간·링크도
마찬가지다. 페이지마다 필요한 글이 다르고 줄바꿈·강조까지 화면에 맞춰야 해서, 컬렉션 필드로 두면
오히려 손이 더 간다.

Firestore `projects`가 맡는 것은 따로 있다.

| 어디 | 무엇 |
|---|---|
| Firestore `projects` | 전시 칸 개수, 이름판에 적는 이름, 로비 책의 목록, `key` |
| `contents/<key>/` | 페이지에 보이는 글과 자료 전부 |

페이지 컴포넌트는 그 Firestore 문서를 props로 받지만 **쓰지 않아도 된다.**

## 6. 등록과 장 이름

`contents/<key>/`에 페이지 컴포넌트를 만들고 `contents/index.ts`의 `PROJECT_PAGES`에 번호로 등록한다.
등록하기 전까지는 자리표시 페이지(이름 + `1 / 3`)가 나온다.

**장 이름은 역할로만 짓고 프로젝트 이름을 넣지 않는다.** 어느 프로젝트인지는 폴더 경로가 말한다.
그래야 프로젝트가 달라도 같은 역할의 장을 같은 이름으로 찾는다.

```text
contents/
  index.ts            # key → 페이지 목록
  contents.types.ts   # 페이지 한 장이 받는 것
  PlaceholderPages/   # 등록 전 칸이 쓰는 자리표시
  shared/             # 장들이 함께 쓰는 부품
    PageIcon/         # 그림 한 장
    PageLink/         # 눌러서 새 탭으로 여는 링크 아이콘
    IntroPage/        # 첫 장의 배치와 크기·간격
  0/
    index.ts          # 이 프로젝트의 페이지 목록
    Intro/            # 첫 장 — 글과 링크만 넘긴다
```

## 7. 한 프로젝트를 채우는 단계

**자료를 미리 다 모아 두지 않는다.** 장을 하나씩 만들면서 그 장에 필요한 것만 그때 넣는다.
어떤 캡처가 필요한지는 그 장을 짜 봐야 정해지고, 미리 모으면 쓰지 않는 자료가 쌓인다.

1. **장 구성 정하기** — 순서는 표준대로, 장수는 담을 내용에 맞춰
2. **장 하나 만들기** — 그 장에 들어갈 글을 정하고, **그 장에 필요한 자료만**
   `public/images/projects/<key>/`에 넣은 뒤 `contents/<key>/`에 컴포넌트 하나를 만든다
3. **확인** — 개발 서버에서 그 장을 보고 다음 장으로 넘어간다. 2~3을 장마다 되풀이한다
4. **마무리** — 장이 다 차면 `PROJECT_PAGES` 등록을 확인하고 `npx tsc -b` · `npm run lint`를 돌린다

**등록은 첫 장에서 한 번 한다.** 등록해야 화면에 뜨므로, 첫 장을 만들 때 `PROJECT_PAGES`에 그 프로젝트를
올려 두고 이후에는 만든 장을 목록에 더한다.

## 8. 공통 부품

`contents/shared/`에 둔다. 장을 만들며 되풀이되는 것이 보이면 이쪽으로 옮긴다.

- **`PageIcon`** — 그림 한 장. 크기는 세로 기준이고 가로는 그림 비율에서 나온다.
- **`PageLink`** — `PageIcon` 위에 누르는 판을 얹어 새 탭으로 연다. 손가락 커서가 붙는다.
- **`IntroPage`** — 첫 장의 배치. 프로젝트 폴더의 `Intro/`는 글과 링크만 넘기는 껍데기다.
  성과 첫 줄 앞 아이콘(`firstIcon`)은 주지 않으면 두지 않는다. 수상이 없는 프로젝트가 있다.

**첫 장의 크기·간격은 모든 전시 칸이 함께 쓴다.** 형식이 같으니 값도 같아야 하고, 개발용 HUD("전시 공간 →
첫 장")에서 맞추면 모든 칸에 함께 적용된다. 확정한 값은 `IntroPage.constants.ts`의
`INTRO_PAGE_LAYOUT`에 반영한다.

**이모지는 쓰지 못한다.** 3D 글씨가 서브셋 ttf를 직접 읽어 글리프가 없다. 🏆 같은 것이 필요하면
아이콘 SVG를 그려 `PageIcon`으로 붙인다.

### 아직 없는 것

- **영상 텍스처 부품** — mp4를 판에 얹고 보이지 않는 동안 멈추는 것
- **글 배치 부품** — 제목·본문 배치가 장마다 되풀이되면 그때 뽑는다
